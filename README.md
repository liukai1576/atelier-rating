# 工作坊评分台（本地版）

这是一个在本机运行的 Node.js 项目。评委通过浏览器打分，项目资料从飞书多维表格读取，保存评分时写回同一个多维表格应用。

## 环境要求

- Node.js 20.9 或更高版本
- npm 10 或更高版本
- `lark-cli` 1.0.68 或更高版本

可以用下面的命令确认：

```bash
node -v
npm -v
lark-cli --version
```

## 启动方式

### macOS

双击项目目录中的 `start-local.command`。

也可以打开终端执行：

```bash
cd /Users/liukai/dev/atelier-score-desk-local
npm install
npm run dev
```

然后访问：

```text
http://localhost:3210
```

### Windows

双击 `start-local.bat`，或者在项目目录中执行：

```bat
npm install
npm run dev
```

## 生产模式

```bash
npm run build
npm run start
```

## 连接飞书多维表格

### 1. 准备数据表

在一个多维表格应用中建立以下数据表。可以直接导入项目目录 `bitable-templates` 中的 CSV 模板。

#### 项目

第一列必须是文本字段 `项目名称`。其余字段：

| 字段 | 建议类型 | 说明 |
| --- | --- | --- |
| 工作坊ID | 文本 | 同一场活动使用同一个稳定 ID |
| 工作坊名称 | 文本 | 顶部显示名称 |
| 工作坊编号 | 文本 | 例如 WS-024 |
| 日期 | 日期或文本 | 活动日期 |
| 地点 | 文本 | 活动地点 |
| 奖项名称 | 文本 | 例如“最具启发奖” |
| 提名上限 | 数字 | 每位评委最多提名数 |
| 项目ID | 文本 | 项目稳定 ID，不要重复 |
| 项目组 | 文本 | 团队名称；未配置独立项目组表时的兼容回退值 |
| 项目组ID | 文本 | 与“项目组”配置表中的稳定 ID 对应 |
| 赛道 | 文本 | 项目类别 |
| 一句话介绍 | 文本 | 项目摘要 |
| 项目资料 | 多行文本 | 评委阅读的详细资料 |
| 路演时长 | 文本 | 例如“8 分钟路演 · 4 分钟问答” |
| 排序 | 数字 | 项目出场顺序 |
| 启用 | 复选框 | 未勾选的项目不会显示 |

#### 项目组

第一列必须是文本字段 `项目组名称`。其余字段：

| 字段 | 建议类型 | 说明 |
| --- | --- | --- |
| 项目组ID | 文本 | 稳定 ID，不要重复；项目表通过它读取配置 |
| 负责人 | 文本 | 项目组负责人 |
| 成员 | 文本 | 成员名单 |
| 项目组简介 | 多行文本 | 前台项目卡片中的团队介绍 |
| 资料链接 | URL | 项目组公共资料入口 |
| 启用 | 复选框 | 未勾选的项目组不会参与映射 |

配置 `FEISHU_TEAMS_TABLE_ID` 后，前台优先使用该表中的项目组名称和资料；项目表中的 `项目组` 文本仅作为找不到 ID 时的回退。

#### 评分

第一列必须是文本字段 `评分唯一键`。以下六个评分维度及 `加权总分` 使用数字字段，`提名`、`已锁票` 使用复选框，`提交时间` 使用日期字段，其余使用文本或多行文本：

```text
评分唯一键、工作坊ID、工作坊名称、项目ID、项目名称、项目组、
评委ID、评委姓名、问题定义、用户与业务价值、方案创新性、
可行性与完成度、影响力与可推广性、表达与答辩、加权总分、
提名、评审笔记、提交时间、已锁票
```

系统使用 `工作坊ID::评委ID::项目ID` 作为唯一键。再次保存同一项目时会更新原记录，不会重复新增。

#### 评委（可选）

字段为 `评委姓名`、`评委ID`、`座位号`、`启用`。不配置该表时，评分台使用代码内置的演示评委名单。

### 2. 配置飞书 CLI

1. 在飞书开放平台创建企业自建应用。
2. 开通多维表格记录的读取、新增和更新权限，并发布应用版本。
3. 打开目标多维表格，在“更多 → 添加文档应用”中把该应用加入，并授予可管理权限。
4. 初始化并登录 CLI。默认使用用户身份读写：

```bash
npm install -g @larksuite/cli
lark-cli config init
lark-cli auth login --domain base --profile <你的-profile>
lark-cli auth status --profile <你的-profile> --verify
```

App ID、App Secret、用户 token 和自动刷新均由 `lark-cli` 的凭证库管理，不写入评分台代码或 `.env.local`。

### 3. 配置目标数据表

复制 `.env.example` 为 `.env.local`，只填 CLI profile、base token 和 table ID：

```bash
cp .env.example .env.local
```

如果 CLI 只有一个 profile，`LARK_CLI_PROFILE` 可以留空。配置完成后重启评分台，页面顶部会显示“多维表格已连接”。

## 数据保存逻辑

- 项目组配置：通过 `lark-cli base +record-list` 从独立的 `项目组` 数据表读取；
- 项目资料、工作坊信息：通过 `lark-cli base +record-list` 从 `项目` 数据表读取；
- 每次点击“保存评分”：通过 `lark-cli base +record-upsert` 新增或更新 `评分` 数据表的一行；
- 锁票：通过 `lark-cli base +record-batch-update` 将该评委在当前工作坊的评分统一标为 `已锁票`；
- 未点击保存的草稿：暂存在当前浏览器 `localStorage`，避免误刷新丢失；
- 未配置飞书时：自动进入本地演示模式，不影响界面体验。

## 修改工作坊内容

接入多维表格后，工作坊与项目资料直接在飞书中维护。评分规则仍位于：

```text
app/page.tsx
```

可修改：

- `criteria`：评分维度、权重和评分标准；
- `demoJudges`：未配置评委表时使用的评委名单。

样式位于：

```text
app/globals.css
```
