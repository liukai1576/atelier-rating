# Atelier 工作坊评分台

本项目是一套本地或服务器部署的工作坊评分平台。项目组、参评项目资料、评委名单、评分结果和工作坊配置都持久化在飞书多维表格中；网页负责工作坊接入、展示、评分和管理，不把正式数据写死在代码里。

默认端口：

```text
http://localhost:3210
```

## 1. 数据究竟放在哪里

平台可以同时管理多个工作坊。每个工作坊对应一个飞书多维表格 Base，Base 中包含五张业务表：

| 表名 | 谁填写 | 用途 | 是否允许预先有数据 |
| --- | --- | --- | --- |
| `工作坊` | 活动组织者 | 整场活动的名称、稳定 ID、日期、地点、奖项与统一路演时长 | 是，且只保留一行 |
| `项目组` | 活动组织者 | 项目组名称、负责人、成员、简介、资料链接 | 是 |
| `项目` | 活动组织者 | 单个参评项目的资料、背景图、项目组关联与出场顺序 | 是 |
| `评委` | 活动组织者 | 评委姓名、稳定 ID、座位号 | 是 |
| `评分` | 系统自动写入 | 每位评委对每个项目的评分、提名、笔记和锁票状态 | 新活动应保持空白 |

此外，平台连接一个长期使用的“配置中心 Base”。其中的 **`评分项目配置`** 表（为兼容现有数据保留这个表名）保存所有已接入工作坊的名称、Base Token 和五张 table ID。它解决了服务器重启或重新部署后工作坊列表丢失的问题。

### 1.0 不通过聊天窗口创建新工作坊

配置功能与评委端完全分离。管理员访问：

```text
http://localhost:3210/admin
```

输入 `ATELIER_CONFIG_ADMIN_KEY` 后，按以下流程操作：

1. 点击“打开标准空白模板”，在飞书中复制一份；
2. 在复制出的 Base 中填写一行 `工作坊`，再填写 `项目组`、`项目` 和 `评委`，`评分` 表保持空白；
3. 回到配置后台，填写唯一对外显示的“工作坊名称”；
4. 粘贴复制后 Base 的链接；
5. 点击“校验并加入系统”。

系统会自动完成：

- 从 Base 链接提取 Base Token；
- 按名称识别 `工作坊`、`项目`、`项目组`、`评委`、`评分` 五张表；
- 校验必需字段和 `项目背景图` 附件字段；
- 把连接坐标写入飞书 `评分项目配置` 表；
- 生成该工作坊固定的评委链接；
- 立即读取新 Base，不需要修改服务器环境变量或重新部署。

新接入工作坊默认启用。管理员可以在 `/admin` 中修改名称：系统会先直接修改该工作坊对应的飞书 Base 文件名，成功后再同步配置中心的显示名称；不会只改网页里的别名。管理员也可以选择“从评委端隐藏”或“启用并展示”。准备中的工作坊应保持隐藏，评委端只会读取已启用工作坊的名称和 ID，不会获得 Base Token、table ID 或配置入口。

### 1.0.1 给评委发送专属链接

每个工作坊都有独立评委链接：

```text
https://你的评分台域名/?app=<工作坊配置ID>
```

无需手工拼接。管理员在 `/admin` 的项目卡片中点击“复制评委链接”，再把该链接发给对应工作坊的评委。

- 评委页面不提供工作坊下拉框；
- 链接中的 `app` 参数固定本次评分所连接的 Base；
- 根地址没有 `app` 参数时自动进入排序第一的已启用工作坊，并在地址栏补齐对应 `app` 参数；
- 已隐藏、已停用或不存在的工作坊链接会显示“需要工作坊专属链接”；
- 不同工作坊使用不同链接，评分写入各自配置的飞书 `评分` 表。

如果 Base 缺表、字段名不对，或者机器人没有访问权限，界面会显示具体错误，不会保存一条不可用配置。

### 1.1 在哪里填写工作坊信息

整场活动的配置只填写在 Base 的 **`工作坊` 表**，并且只保留一行。不要把这些字段重复放进每个项目。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 工作坊名称 | 文本，主字段 | 是 | 与 Base 文件名、配置后台名称同步 |
| 工作坊ID | 文本 | 是 | 稳定技术主键；用于评分唯一键，创建后不要修改 |
| 日期 | 文本或日期 | 建议 | 整场活动日期 |
| 地点 | 文本 | 建议 | 整场活动地点 |
| 奖项名称 | 文本 | 建议 | 例如“评委特别奖” |
| 提名上限 | 数字 | 建议 | 每位评委在整场活动中最多提名几个项目 |
| 路演时长 | 文本 | 可选 | 整场活动统一规则，例如“8 分钟路演 · 4 分钟问答” |

没有 `工作坊编号`：它与稳定的 `工作坊ID` 重复，已经从 schema 和界面移除。`提名` 本身不是配置字段，而是评委对单个项目的评分结果，仍写入 `评分` 表。

从旧版迁移的 Base 会先保留项目表中的旧工作坊列作为回滚备份，但平台不再读取它们。确认新工作坊表运行正常后，可以删除这些旧列；全新模板和建表脚本不会再创建它们。

### 1.2 在哪里填写参评项目信息

项目的主数据填写在 Base 的 **`项目` 表**。

每一行代表一个项目。系统通过服务端调用：

```text
lark-cli base +record-list
```

读取 `.env.local` 中 `FEISHU_PROJECTS_TABLE_ID` 指向的数据表，并按以下规则组装页面：

- `排序` 决定评分页项目顺序；
- `启用` 未勾选的项目不会显示；
- `项目组ID` 用来匹配 `项目组` 表；
- `项目ID` 是稳定业务 ID，不要随意修改或重复；
- `项目背景图` 会同时用于评分页项目识别和颁奖大屏。

`项目` 表字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 项目名称 | 文本，主字段 | 是 | 页面和颁奖台显示名称 |
| 项目ID | 文本 | 是 | 稳定且唯一，例如 `project-001` |
| 项目组ID | 文本 | 是 | 对应 `项目组` 表中的稳定 ID；名称可改、可重名，因此不能用名称关联 |
| 赛道 | 文本 | 建议 | 项目类别 |
| 一句话介绍 | 文本 | 建议 | 评分页和颁奖台摘要 |
| 项目资料 | URL | 可选 | 路演材料或详细说明链接 |
| 项目背景图 | **附件** | 强烈建议 | 上传一张 JPG、PNG 或 WebP |
| 排序 | 数字 | 是 | 1、2、3…… |
| 启用 | 复选框 | 是 | 勾选后才会显示 |

### 1.3 项目组配置在哪里

项目组信息填写在 **`项目组` 表**。推荐先填写项目组，再填写项目。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 项目组名称 | 文本，主字段 | 页面显示名称 |
| 项目组ID | 文本 | 稳定且唯一，与项目表对应 |
| 负责人 | 文本 | 项目负责人 |
| 成员 | 文本 | 成员名单 |
| 项目组简介 | 多行文本 | 评分页展示 |
| 资料链接 | URL | 项目组公共资料 |
| 启用 | 复选框 | 未勾选时不参与匹配 |

### 1.4 评分最终写到哪里

所有正式评分写入同一 Base 的 **`评分` 表**，表 ID 由：

```text
FEISHU_SCORES_TABLE_ID
```

指定。

评委点击“保存”后，服务端执行：

```text
lark-cli base +record-upsert
```

系统以：

```text
工作坊ID::评委ID::项目ID
```

作为 `评分唯一键`。同一评委再次保存同一项目时会更新原记录，不会新增重复记录。

锁票时，系统执行：

```text
lark-cli base +record-batch-update
```

把该评委在当前工作坊的全部记录设置为 `已锁票=true`。

`评分` 表包含：

```text
评分唯一键、工作坊ID、工作坊名称、项目ID、项目名称、项目组、
评委ID、评委姓名、问题定义、用户与业务价值、方案创新性、
可行性与完成度、影响力与可推广性、表达与答辩、加权总分、
提名、评审笔记、提交时间、已锁票
```

未点击“保存”的草稿只保存在当前浏览器 `localStorage`；它不是最终数据。服务器部署后，判断正式结果时应以飞书 `评分` 表为准。

## 2. 项目背景图片

`项目背景图` 必须是飞书 **附件字段**，推荐每个项目上传一张图片：

- 推荐比例：16:9；
- 推荐尺寸：1920×1080 或更高；
- 格式：JPG、PNG、WebP；
- 建议体积：10 MB 以内；
- 一行只放一张主图。

用途：

1. **评分阶段**：显示在项目摘要左侧，帮助评委快速区分项目；
2. **颁奖阶段**：颁奖大屏左侧显示奖项、项目名与团队，右侧整幅显示获奖项目图片，方便获奖人站在屏幕前合影；
3. 未上传图片时，系统使用内置的颜色与项目首字作为回退，不会出现破图。

附件不会直接暴露飞书令牌。浏览器请求：

```text
/api/bitable/project-image
```

服务端再通过 `lark-cli base +record-download-attachment` 下载飞书附件并返回图片。

## 3. 创建新的飞书 Base

### 推荐方式：使用结构创建脚本

不要只靠 CSV 导入来新建表结构。CSV 无法可靠创建附件、日期和复选框字段，尤其会把 `项目背景图` 错建成普通文本。

先完成第 4 节的 CLI 配置，然后运行：

```bash
npm run create:base -- --name "Atelier 评分台 · 我的工作坊" --as user --profile <你的-profile>
```

如果服务器只配置了机器人身份：

```bash
npm run create:base -- --name "Atelier 评分台 · 我的工作坊" --as bot --profile <你的-profile>
```

脚本位于：

```text
scripts/create-feishu-base.mjs
```

它会创建：

- 空的 `项目` 表；
- 空的 `项目组` 表；
- 空的 `评委` 表；
- 空的 `评分` 表；
- 正确的附件、数字、日期和复选框字段；
- 一段可复制到 `.env.local` 的配置。

机器人身份创建的 Base 可能不会自动授予当前用户访问权限。此时需要在飞书文档权限中把自己加入，或先使用 `lark-cli auth login` 登录用户身份后再创建。

### CSV 模板什么时候用

`bitable-templates` 目录中的 CSV 用于**批量填充数据**，不是首选的建表工具：

| 模板 | 导入到 |
| --- | --- |
| `项目组.csv` | `项目组` 表 |
| `项目.csv` | `项目` 表 |
| `评委.csv` | `评委` 表 |
| `评分.csv` | `评分` 表，仅用于确认列结构；新活动不要导入示例评分 |

正确顺序：

1. 用创建脚本建立 Base 和字段；
2. 导入或填写 `项目组`；
3. 导入或填写 `项目`；
4. 上传每个项目的 `项目背景图`；
5. 导入或填写 `评委`；
6. 确认 `评分` 表为 0 条记录；
7. 配置 `.env.local` 并启动平台。

## 4. 配置飞书 CLI

### 4.1 飞书开放平台应用

在飞书开放平台创建企业自建应用，并开通完成以下操作所需的多维表格权限：

- Base、数据表和字段读取；
- 记录读取、新增和更新；
- 附件上传和下载；
- 创建新 Base 和数据表（仅使用一键创建脚本时需要）。

发布应用版本，并确保该应用可以访问目标 Base。

### 4.2 安装和登录 CLI

```bash
npm install -g @larksuite/cli
lark-cli config init
lark-cli auth login --domain base --profile <你的-profile>
lark-cli auth status --profile <你的-profile> --verify
```

本项目不保存 App Secret。App ID、App Secret、用户 token 和自动刷新 token 均由 `lark-cli` 凭证库管理。

服务器部署推荐使用机器人身份：

```text
LARK_CLI_IDENTITY=bot
```

同时确保机器人应用已被授予目标 Base 的访问权限。

## 5. 配置环境变量

复制模板：

```bash
cp .env.example .env.local
```

填写：

```dotenv
LARK_CLI_PROFILE=<你的-profile>
LARK_CLI_IDENTITY=bot
LARK_CLI_BIN=/absolute/path/to/lark-cli

FEISHU_BITABLE_APP_TOKEN=<base-token>
FEISHU_WORKSHOPS_TABLE_ID=<工作坊表-ID>
FEISHU_PROJECTS_TABLE_ID=<项目表-ID>
FEISHU_SCORES_TABLE_ID=<评分表-ID>
FEISHU_TEAMS_TABLE_ID=<项目组表-ID>
FEISHU_JUDGES_TABLE_ID=<评委表-ID>

# 多工作坊配置中心
FEISHU_REGISTRY_BASE_TOKEN=<配置中心-Base-Token>
FEISHU_REGISTRY_TABLE_ID=<评分项目配置表-ID（兼容现有表名）>
FEISHU_TEMPLATE_BASE_URL=<标准空白模板-Base-URL>

# 必填；保护独立的 /admin 配置后台
ATELIER_CONFIG_ADMIN_KEY=<管理密钥>
```

配置中心表需要包含以下字段：

```text
配置名称、配置ID、Base链接、BaseToken、工作坊表ID、项目表ID、评分表ID、
项目组表ID、评委表ID、启用、排序、创建时间、备注
```

`FEISHU_BITABLE_APP_TOKEN` 和五个业务 table ID 仍作为兼容性的默认工作坊使用。配置中心启用后，新工作坊全部通过 `/admin` 配置后台接入。

`ATELIER_CONFIG_ADMIN_KEY` 必须设置。管理密钥只随当前管理请求发送，不会写入飞书配置表；未设置时，配置读取和写入接口都会拒绝管理操作。评委端不会显示管理入口。

管理密钥由服务器本地校验，不依赖飞书网络。验证成功后才读取飞书配置；若飞书 token 接口出现临时 EOF 或网络重置，服务端会自动重试最多 3 次，管理员也可以在后台点击“重新读取配置”。

配置完成后必须重启应用。页面顶部应显示：

```text
多维表格已连接
```

如果 Base 已连接但项目表为空，页面会显示“空白评分应用已就绪”，而不会回退到演示数据。

## 6. 本地运行

环境要求：

- Node.js 20.9 或更高；
- npm 10 或更高；
- `lark-cli` 已完成配置。

```bash
cd /Users/liukai/dev/atelier-score-desk-local
npm install
npm run dev
```

访问：

```text
http://localhost:3210
```

macOS 也可以双击 `start-local.command`，Windows 可以双击 `start-local.bat`。

## 7. 部署到服务器

服务器上同样必须安装并配置 `lark-cli`。仅部署 Next.js 代码而没有 CLI 凭证，应用无法读取真实飞书数据。

推荐流程：

```bash
npm ci
npm run build
npm run start
```

部署检查：

1. 服务器的 `.env.local` 指向正确的真实 Base；
2. `lark-cli auth status --verify` 返回可用；
3. `/api/bitable/bootstrap` 返回 `connected: true`；
4. 页面顶部显示“多维表格已连接”；
5. 新建一份测试评分，确认飞书 `评分` 表出现对应记录；
6. 上传一张背景图，确认评分页和颁奖演示模式都能显示；
7. 反向代理必须允许访问 `/api/bitable/*`，不要把这些路径缓存为静态页面。

生产环境不要依赖本地演示模式。页面若显示“本地演示数据”，应先修复飞书连接再开放给评委。

## 8. 评分与颁奖流程

1. 组织者填写项目组、项目和评委；
2. 评委选择自己的名字；
3. 对每个项目填写六个维度、提名和笔记；
4. 点击保存，评分立即写入飞书；
5. 全部项目完成后锁票；
6. 管理总览查看进度和实时排名；
7. 数据达到 100% 后打开颁奖台；
8. 点击“演示模式”进入全屏大屏版；
9. 奖项左侧显示获奖信息，右侧显示项目背景图。

## 9. 常见问题

### 页面显示本地演示数据

检查：

- `.env.local` 是否存在并已重启；
- Base token 与 table ID 是否正确；
- CLI profile 是否有效；
- 应用是否有 Base 和记录读取权限；
- 服务器是否能访问飞书开放平台。

### 项目背景图不显示

检查：

- 字段名是否精确为 `项目背景图`；
- 字段类型是否为“附件”；
- 是否上传了 JPG、PNG 或 WebP；
- 飞书应用是否有附件下载权限；
- `/api/bitable/project-image` 是否返回 `200` 和正确图片类型。

### 评分没有写入

检查 `评分` 表字段名是否与本文一致，并查看服务端日志中的 `[bitable scores POST]`。

### 新 Base 打开后没有项目

这是正常的空白配置态。管理员进入 `/admin` 打开对应 Base，填写项目组、项目和评委，保持评分表为空；完成后再把项目设为“启用并展示”。
